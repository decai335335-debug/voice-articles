## 📖 使用方法

**场景一：研究语音命名体系**
- 从《鸣潮》文档了解 Event → VO 的映射逻辑
- 对比《英雄联盟》的分类体系，理解不同游戏类型的命名差异

**场景二：设计开放世界语音系统**
- 阅读《开放世界语音系统设计研究大纲》，获取从顶层架构到底层实现的完整框架
- 重点参考「多智能体通信语义栈」和「运行时解析调度」章节

**场景三：分析声优表演**
- 以《秦紫翼五角色分析》为模板，学习如何量化拆解声优的多角色表演

**场景四：优化团队协作**
- 阅读《跨岗位协作深度研究》，获取 Event 共享字典模板、工作坊议程设计等实操工具

## 🧰 研究方法

- **逆向工程分析**：解析客户端 Wwise 事件数据
- **数据统计**：对 24K+ 事件进行 Token 频率、前缀树深度、路由模式等定量分析
- **比较研究**：跨游戏（鸣潮 vs LoL）、跨平台（PC/移动/主机）对比
- **框架推导**：从现有体系逆向推导设计原则，构建抽象设计框架
- **参数化分析**：将声优表演拆解为可量化的声音参数组合

## ❓ 常见问题

**Q: 这些研究数据来源是什么？**
A: 主要来自对游戏客户端资源的逆向分析，以及公开的 Wwise 工程数据。研究中不包含受版权保护的游戏资产本身。

**Q: 研究适用于什么职位？**
A: 游戏音频设计师、语音导演、系统策划、叙事设计师、技术音频工程师。

**Q: 能否商用参考？**
A: 研究内容本身可自由参考。但请注意，文中引用的游戏名称（如《鸣潮》、《英雄联盟》）和相关术语分属各自版权方。
